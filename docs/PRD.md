# FutureShift AI — 产品需求工作文档

> Navigate change. Shape your future.
>
> 定位：帮助用户为多种可能的职业未来做好准备。
> 依据：本仓库 `docs/reference/domain-1-brief.pdf`，尤其第 4–8 页（PDF 页码）。本文是工作文档，正式提交须转入官方模板并核对篇幅要求。

## 状态说明

- 已实现：开发前目录与文档骨架；本工作文档已补充需求。尚无应用功能或运行验证。
- 计划中：本文描述的问卷、雷达、匹配、情景、学习计划及 SDG 展示。
- 待验证：数据访问与许可、趋势计算有效性、匹配质量、课程可用性、模型与部署方案。验收标准是未来检查要求，不代表已通过。

## 问题

学生和应届毕业生难以将自身能力、变化中的 AI 与劳动力市场信号转化为可解释的职业选择和学习行动。静态职业清单无法说明变化原因，单一预测容易制造确定性错觉。产品支持用户判断，不代替个人职业决定或作出招聘决定。

## 目标用户

预赛聚焦学生与应届毕业生，使用场景是毕业前后的职业探索和初步技能规划。工作成年人、转行者、HR 和职业中心属于后续扩展对象。

## 核心用户流程

1. 问卷：填写技能及自评水平、学习经历、兴趣、每周可学习时间与预算偏好。演示只使用明确标记的合成画像。
2. 用户确认画像：展示规范化技能及映射，允许修改、确认，之后固定画像版本。
3. 趋势雷达与情景选择：展示信号方向、原始来源、发布日期、获取日期、覆盖范围及局限，同时显示 moderate 与 fast disruption 两种结果，并可切换主视图。
4. 展示前五个职业：按规则分数排序，给出分项解释、技能缺口、来源、情景和 SDG 贡献。
5. 个性化学习计划：按先修关系和技能缺口安排步骤，显示核验过的资源、预计时间、费用信息及来源。

### 核心演示：数据更新驱动可追溯变化

固定合成画像、情景、职业目录与评分规则版本，先用来源快照 A 计算，再获取同一可更新来源的较新快照 B，展示前五职业排序及解释的变化。记录快照标识、内容摘要哈希、来源日期、获取日期、信号差异、分项分数和名次差异。变化必须来自新数据经信号计算进入匹配公式，解释读取同一计算记录。

若真实更新未改变排名，应如实展示无变化及原因，并继续验证信号和数据窗口，不能强行改分。为了验收可另用明确标记的合成测试输入验证计算敏感性；它不替代真实来源更新的核心演示。历史真实快照回放须标记“历史回放”，不能称作实时获取。

### 情景与不确定性

moderate 与 fast disruption 是趋势权重不同的探索性情景，不能解释为确定的 AI 替代速度、就业增长率或个人就业概率。两者同时显示，参数与敏感性遵循下述评分设计；数据不足时显示原因，不推断增长结论。

## 预赛原型评分设计（已确定设计，尚未实现）

### 用户技能与职业要求

用户对每项技能选择 0–4：

| 值 | 含义 |
| --- | --- |
| 0 | no exposure |
| 1 | basic awareness |
| 2 | applied with guidance |
| 3 | independently applied |
| 4 | advanced |

用户值按 `user_i = raw_user_i / 4` 转换到 0–1。每个职业只使用已选定且可追溯到 O*NET 31.0 的核心技能；职业要求转换到 0–1，按所选 O*NET 字段官方量表的上下界进行线性归一化，保存字段、原值、上下界和转换规则。具体字段及量表语义待验证，不能假定用户自评与职业要求天然等价。importance_i 使用非负的 O*NET 重要性权重，保存原字段和归一化规则，不以缺失值代替 0。

### 技能覆盖分与缺口

`coverage_i = min(user_i / required_i, 1)`

`S_skills = 100 × sum(importance_i × coverage_i) / sum(importance_i)`

`required_i = 0` 的项目不参与覆盖分的分子或分母；超出要求不增加超过 100% 的覆盖。S_skills 为 0–100。没有有效技能或有效权重和为 0 时，S_skills 为不可计算，不能补为 0。

`gap_i = importance_i × max(required_i − user_i, 0)`

按 gap_i 从高到低展示 skills-gap breakdown，正缺口用于学习计划；并列按稳定技能 ID 排序。零要求项目的缺口为 0。所有输入、映射和转换版本固定后，结果必须确定且可复现。

### 知识覆盖与能力分

K_knowledge 使用与 S_skills 相同的用户值 `/4`、O*NET 要求归一化、importance weighting 和封顶 coverage 逻辑：

`K_knowledge = 100 × sum(knowledge_importance_j × min(user_knowledge_j / required_knowledge_j, 1)) / sum(knowledge_importance_j)`

仅对 required_knowledge_j > 0 的已验证核心知识项求和；分母为 0 或必要数据缺失时不可计算，不补零或静默调整组件权重。

`S_capability = 0.75 × S_skills + 0.25 × K_knowledge`

0.75 / 0.25 为待验证原型参数。知识缺口为 `knowledge_gap_j = knowledge_importance_j × max(required_knowledge_j − user_knowledge_j, 0)`。分别显示 **Skills gaps** 与 **Knowledge gaps**，各按 gap 降序、稳定元素 ID 打破并列。专业名称不能直接转换为能力分。职业核心字段仅从问卷已询问且可追溯到 O*NET 的项目中预先选择，披露覆盖局限。

### RIASEC 兴趣分与个人适配

使用顺序固定为 Realistic、Investigative、Artistic、Social、Enterprising、Conventional 的六维非负向量。用户向量来自短问卷，职业向量来自 O*NET；保存问卷计分规则及职业字段来源，原创题项及用户计分见 [QUESTIONNAIRE.md](QUESTIONNAIRE.md)，职业字段待验证。

`I = 100 × dot(user_RIASEC, role_RIASEC) / (norm(user_RIASEC) × norm(role_RIASEC))`

I 为 cosine similarity × 100，范围 0–100。任一维缺失、数值无效或任一向量范数为 0 时，显示具体原因；用户可补全问卷，职业数据可补核验。降级仅展示可计算的 S_skills、K_knowledge 和两组缺口，不计算 I、P 或情景总分，也不让该职业进入完整情景排名；不静默用零、均值或重新分配权重。S_skills 或 K_knowledge 缺失时同样停止该职业完整评分。

`P = 0.70 × S_capability + 0.30 × I`

个人适配 P 范围为 0–100，权重为已确定的预赛原型设计，其有效性仍待验证。

### GitHub 技术趋势分

对每个预定义且有说明的技术主题 k：

`T_k = 50 + 50 × clip(log2((Recent_k + 20) / (Previous_k + 20)), −1, 1)`

Recent_k 为最近 90 天新建公开仓库数，Previous_k 为此前 90 天新建公开仓库数。20 是原型平滑参数，属于待验证假设；clip 将对数比值限制到 −1 至 1，T_k 范围为 0–100。两个计数均为 0 时公式返回 50，但须同时显示零样本，不得解释为有充分证据的稳定趋势。

`T = sum(topic_weight_k × T_k) / sum(topic_weight_k)`

每个职业仅使用与其明确映射的技术主题，权重非负、总和大于 0；映射、权重和依据均版本化并待验证。缺少必要主题的有效计数或映射时，不静默删掉主题重分配权重，不计算完整 T 和情景总分；可展示 P 并说明趋势缺失。优先按缓存规则使用最后一次成功的完整快照。

界面逐主题显示原始计数、两个时间窗、查询词、更新时间、来源 URL、映射和聚合权重。该指标只代表开源技术活动动量，不是就业需求、工资、就业增长或职业前景概率。

### 情景总分与敏感性

`Match(lambda) = (1 − lambda) × P + lambda × T`

- moderate scenario：`lambda = 0.15`。
- fast disruption scenario：`lambda = 0.35`。

总分范围为 0–100。两种情景仅改变 lambda，不修改用户画像、O*NET 数据、原始趋势快照、主题映射或其他计算规则。这些参数是预赛原型情景假设，尚不是经过验证的就业预测。

同时显示 moderate 与 fast 两种结果，保留切换主视图的能力。对同一职业展示 `score_delta = Match(0.35) − Match(0.15)` 和 `rank_delta = rank_moderate − rank_fast`，后者正值表示 fast 中名次上升；两种排名使用同一批可完整评分的职业。同分按稳定职业 ID 排序。对比称为 scenario sensitivity，不称为统计置信度。

显示趋势原始样本量，以及缺失、`cached`、过期状态和时间；过期阈值待验证，未配置时明确显示未配置。简单样本量阈值只能作为数据提示，不是统计置信度。

### SDG 与模型边界

SDG 在预赛版本中不进入匹配总分。独立展示职业、技能、SDG 映射依据及贡献解释，可用于筛选或比较，不能无证据加分。筛选只改变显示集合，不改变原始分数；情景敏感性保留统一候选集合的排名口径。

大模型不得计算、覆盖或“优化”S_skills、K_knowledge、S_capability、I、P、T、gap、情景分数及排名；只读取规则引擎的结果和来源生成受约束解释。界面追溯原始输入、归一化值、coverage、importance、gap、RIASEC 向量、主题计数和 T_k、聚合 T、S_skills、K_knowledge、S_capability、P、lambda 及总分。规则引擎按固定 ID 顺序聚合，使用版本化数值精度策略；排序使用未作展示舍入的分数，舍入仅用于显示，确保同输入和同快照完全复现。

## 后续范围与边界

后续功能：CV 解析、HR 团队视图、学习打卡、多语言、自动重新规划与更完整的公平性评估。CV 解析仍需另行确定隐私与授权方案；本次所有演示禁止使用真实 CV 或真实个人资料。

不包含完整课程内容生成、支付系统和真实招聘集成。未经核验的职业、课程、链接或统计不得进入推荐；模型无法提供有效引用时不展示该项推荐。

## 可检查的验收标准（均待执行）

1. 合成画像可从问卷进入确认页，修改技能后保存新版本；演示素材不含真实身份信息或 CV。
2. 至少一个实际可更新来源完成获取与快照保存，页面显示可核验出处、发布日期和获取日期；未知日期明确标记未知。固定列表或模拟按钮不算更新。
3. 在固定画像、规则、情景和目录的条件下，用两份不同日期的真实来源快照完成对比：信号进入公式，趋势变化通过公式改变 T、总分或排名；对非饱和且 T 不同的快照必须产生总分变化，名次变化作为核心演示目标而非强制改分条件；解释指出对应证据和分项变化。仅更改文案不通过。
4. 相同输入、相同数据快照和相同版本得到完全相同的全部中间分数、总分和顺序；分项可手工复算。另用合成测试输入检查信号变化的数值传递，确认数据更新不是只修改展示层。
5. 前五职业均来自已核验目录，展示分数构成、缺口和有效引用；不足五个可信候选时报告不足，不能补造职业。
6. 同时显示两种情景、分数差和排名差；切换情景仅改变 lambda（0.15 / 0.35），画像、O*NET 和原始趋势数据不变。显示原始样本量及缺失、缓存、过期状态，不把简单阈值称为统计置信度。
7. 学习计划与已计算缺口对应，包含有序步骤、先修关系、预计时间、免费或低价资源及核验日期；无可靠资源的缺口标记待补充。预计时间须区分提供方时长与项目估算。
8. 所有展示职业及技能至少有一个 SDG 映射、目标编号和具体贡献解释；不得把关联标签说成已实现的社会影响。SDG 独立展示，不进入匹配总分；可用于筛选或比较但不能无证据加分。优先审查官方强调的 4.3、4.4、8.2、8.5。
9. 每项推荐均能追溯到职业、技能、趋势及课程等相关证据；所有中间分数可在界面解释和追溯，大模型不得计算、覆盖或“优化”任何分数，也不新增目录外实体或统计。模型声明、引用校验和失败降级可检查。
10. 来源或模型不可用时显示明确状态、缓存日期和限制；不得显示虚假的实时刷新成功。以完整合成画像走通全流程并记录耗时，初步目标为五分钟内获得结果，待用户验证。

## 风险

最大风险是获得合法、可重复更新且能映射到职业技能的趋势数据。先验证最小数据链，再开发界面。其他风险包括地域不适配、稀疏信号、主观评分与情景权重、错误 SDG 关联、失效课程、模型幻觉与职业建议偏差。通过保留来源、版本、缺失标记、人工审查及明确降级减少风险；不将新闻热度直接解释为岗位增长。

## SDG 对齐

以联合国官方目标与具体 targets 为定义依据，重点解释 SDG 4 的技能与学习机会（4.3、4.4）及 SDG 8 的创新生产力与体面就业（8.2、8.5）。每个职业与技能分别保存 SDG、具体贡献机制、来源和人工审查状态。关联应表达“该技能如何支持某项工作活动并可能贡献目标”，不能仅贴图标或承诺就业、收入及可持续影响。

## 问卷、职业池与输入契约

六页问卷见 [QUESTIONNAIRE.md](QUESTIONNAIRE.md)，十个正式职业及来源见 [CAREER_POOL.md](CAREER_POOL.md)。页面依次为背景、11 项技能、7 项知识、12 条原创 RIASEC 题、学习约束与 SDG、画像确认，目标 3–5 分钟（待试填）。不收集姓名、年龄、性别、联系方式或真实 CV。

### 补充验收标准（待执行）

- 每个用户计分输入有问卷题目来源，外部计分输入有 O*NET、GitHub 或规则版本来源，无隐藏背景加分。
- 展示但不计分的字段有明确标签和用途，不询问未使用的个人信息。
- 用户能查看、修改全部用户评分字段；未确认不计算，缺失不静默补值。
- S_skills、K_knowledge、S_capability、I、P、T 和两情景总分均可复算，缺口分两组显示；其他趋势公式及情景权重不变。
- 相同确认画像、快照和版本结果一致；只修改不计分字段不能改变分数。职业名称、代码、官方来源可追溯，候选映射不能冒充最终数据。
