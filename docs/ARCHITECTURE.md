# FutureShift AI — 建议架构

## 状态与最简方案

当前已有标准库评分引擎及 synthetic 测试，尚无网页或真实数据接入。本轮已核实 O*NET 31.0 官方 CSV，但没有接入评分或部署。预赛数据方案已确定为 O*NET 31.0 官方 CSV + GitHub REST Repository Search API。当前建议技术栈收敛为 **Python + Streamlit + CSV/JSON**：一个进程完成界面、数据获取、规则评分及可选模型调用。没有账户系统或长期用户数据，预赛暂不使用 SQLite；CSV 保存小型目录，JSON 保存趋势快照和计算元数据。适合单人短期验证完整计算链，运行环境仍待验证。

## 前端

建议 Streamlit 页面按问卷 → 画像确认 → 雷达与情景 → 前五职业及缺口 → 学习计划组织。展示合成数据标识、来源与日期、情景假设、运行版本、更新前后对比及缓存状态。先满足预赛最关键演示；移动端体验待验证。

## 后端与数据获取

建议与前端同进程，职责分开：

1. 数据获取：O*NET 31.0 选取少量真实职业及技能字段，记录版本、发布日期、来源链接和许可归属；GitHub 按预定义 AI 技能主题获取两个窗口的新建公开仓库计数。O*NET 是美国职业技能基准，不代表马来西亚就业预测。
2. 规则化特征：固定主题映射和查询规则，将最近 90 天与此前 90 天计数转为开源技术活动动量；保存原始计数、计算规则、映射与版本。采用下述对数比值和平滑公式；具体映射及权重有效性待验证，不将动量称为就业需求或工资增长。
3. 情景权重：moderate / fast disruption 只改变趋势信号在总分中的权重；画像、职业技能基准、趋势计算、基础适配分及其他规则保持一致。权重是探索性假设，不是确定预测。
4. 可解释匹配：仅对 O*NET 选定真实职业计算分数和技能缺口，输出分项、权重与引用。
5. AI 解释与学习计划：读取锁定结果和已核验资料；资源选择与先修顺序先由规则约束。

数据流：**O*NET 职业技能数据 + GitHub 趋势快照 → 规则化特征 → 情景权重 → 可解释职业排名**。已确认的合成画像参与基础适配计算，AI 解释与学习计划在排名之后执行。

arXiv API 是后续或备用研究趋势信号，传统接口按最多每 3 秒一次请求设计；预赛核心流程不依赖它。

## 匹配引擎

以下公式已在评分引擎中实现并用 synthetic 数据测试；真实数据适配与有效性验证尚未完成。

### 用户技能与职业要求

用户对每项技能选择 0–4：

| 值 | 含义 |
| --- | --- |
| 0 | no exposure |
| 1 | basic awareness |
| 2 | applied with guidance |
| 3 | independently applied |
| 4 | advanced |

用户值按 `user_i = raw_user_i / 4` 转换到 0–1。每个职业只使用已选定且可追溯到 O*NET 31.0 的核心技能；职业要求转换到 0–1，按所选 O*NET 字段官方量表的上下界进行线性归一化，保存字段、原值、上下界和转换规则。官方字段与量表已核实：建议取 IM（1–5）作重要性，importance=(IM−1)/4；取 LV（0–7）作职业要求，required=LV/7。用户仍用 response/4，不能对 O*NET 原值调用 normalize_0_4。保存原字段、数值、质量标记及转换版本；不以缺失值代替 0。该转换是未校准的项目建议，两个测量体系数值归一化不代表能力语义等价。

### 技能覆盖分与缺口

`coverage_i = min(user_i / required_i, 1)`

`S_skills = 100 × sum(importance_i × coverage_i) / sum(importance_i)`

`required_i = 0` 的项目不参与覆盖分的分子或分母；超出要求不增加超过 100% 的覆盖。S_skills 为 0–100。没有有效技能或有效权重和为 0 时，S_skills 为不可计算，不能补为 0。

`gap_i = importance_i × max(required_i − user_i, 0)`

按 gap_i 从高到低展示 skills-gap breakdown，正缺口用于学习计划；并列按稳定技能 ID 排序。零要求项目的缺口为 0。所有输入、映射和转换版本固定后，结果必须确定且可复现。

### 知识覆盖与能力分

K_knowledge 使用与 S_skills 相同的用户值 `/4`、O*NET 要求归一化、importance weighting 和封顶 coverage 逻辑：

`K_knowledge = 100 × sum(knowledge_importance_j × min(user_knowledge_j / required_knowledge_j, 1)) / sum(knowledge_importance_j)`

仅对 required_knowledge_j > 0 的已验证核心知识项求和；分母为 0 或必要数据缺失时不可计算，不补零或静默调整组件权重。

`S_capability = 0.75 × S_skills + 0.25 × K_knowledge`

0.75 / 0.25 为待验证原型参数。知识缺口为 `knowledge_gap_j = knowledge_importance_j × max(required_knowledge_j − user_knowledge_j, 0)`。分别显示 **Skills gaps** 与 **Knowledge gaps**，各按 gap 降序、稳定元素 ID 打破并列。专业名称不能直接转换为能力分。职业核心字段仅从问卷已询问且可追溯到 O*NET 的项目中预先选择，披露覆盖局限。

### RIASEC 兴趣分与个人适配

使用顺序固定为 Realistic、Investigative、Artistic、Social、Enterprising、Conventional 的六维非负向量。用户向量来自短问卷，职业向量来自 O*NET；保存问卷计分规则及职业字段来源，原创题项及用户计分见 [QUESTIONNAIRE.md](QUESTIONNAIRE.md)，职业端字段已核实为 Career Interest Types 的 OI（1–7），按 (OI−1)/6 转换；只取 R/I/A/S/E/C 六维，不使用 IH 高点代码。跨问卷有效性仍待验证。

`I = 100 × dot(user_RIASEC, role_RIASEC) / (norm(user_RIASEC) × norm(role_RIASEC))`

I 为 cosine similarity × 100，范围 0–100。任一维缺失、数值无效或任一向量范数为 0 时，显示具体原因；用户可补全问卷，职业数据可补核验。降级仅展示可计算的 S_skills、K_knowledge 和两组缺口，不计算 I、P 或情景总分，也不让该职业进入完整情景排名；不静默用零、均值或重新分配权重。S_skills 或 K_knowledge 缺失时同样停止该职业完整评分。

`P = 0.70 × S_capability + 0.30 × I`

个人适配 P 范围为 0–100，权重为已确定的预赛原型设计，其有效性仍待验证。

### GitHub 技术趋势分

对每个预定义且有说明的技术主题 k：

`T_k = 50 + 50 × clip(log2((Recent_k + 20) / (Previous_k + 20)), −1, 1)`

Recent_k 为最近 90 天新建公开仓库数，Previous_k 为此前 90 天新建公开仓库数。20 是原型平滑参数，属于待验证假设；clip 将对数比值限制到 −1 至 1，T_k 范围为 0–100。两个计数均为 0 时公式返回 50，但须同时显示零样本，不得解释为有充分证据的稳定趋势。

`T = sum(topic_weight_k × T_k) / sum(topic_weight_k)`

每个职业仅使用与其明确映射的技术主题，权重非负、总和大于 0；映射、权重和依据均版本化并待验证。缺少必要主题的有效计数或映射时，不静默删掉主题重分配权重，不计算完整 T 和情景总分；可展示 P 并说明趋势缺失。优先按缓存规则使用最后一次成功的完整快照。

界面逐主题显示原始计数、两个时间窗、查询词、更新时间、来源 URL、映射和聚合权重。该指标只代表开源技术活动动量，不是就业需求、工资、就业增长或职业前景概率。

### 情景总分与敏感性

`Match(lambda) = (1 − lambda) × P + lambda × T`

- moderate scenario：`lambda = 0.15`。
- fast disruption scenario：`lambda = 0.35`。

总分范围为 0–100。两种情景仅改变 lambda，不修改用户画像、O*NET 数据、原始趋势快照、主题映射或其他计算规则。这些参数是预赛原型情景假设，尚不是经过验证的就业预测。

同时显示 moderate 与 fast 两种结果，保留切换主视图的能力。对同一职业展示 `score_delta = Match(0.35) − Match(0.15)` 和 `rank_delta = rank_moderate − rank_fast`，后者正值表示 fast 中名次上升；两种排名使用同一批可完整评分的职业。同分按稳定职业 ID 排序。对比称为 scenario sensitivity，不称为统计置信度。

显示趋势原始样本量，以及缺失、`cached`、过期状态和时间；过期阈值待验证，未配置时明确显示未配置。简单样本量阈值只能作为数据提示，不是统计置信度。

### SDG 与模型边界

SDG 在预赛版本中不进入匹配总分。独立展示职业、技能、SDG 映射依据及贡献解释，可用于筛选或比较，不能无证据加分。筛选只改变显示集合，不改变原始分数；情景敏感性保留统一候选集合的排名口径。

大模型不得计算、覆盖或“优化”S_skills、K_knowledge、S_capability、I、P、T、gap、情景分数及排名；只读取规则引擎的结果和来源生成受约束解释。界面追溯原始输入、归一化值、coverage、importance、gap、RIASEC 向量、主题计数和 T_k、聚合 T、S_skills、K_knowledge、S_capability、P、lambda 及总分。规则引擎按固定 ID 顺序聚合，使用版本化数值精度策略；排序使用未作展示舍入的分数，舍入仅用于显示，确保同输入和同快照完全复现。

## AI 组件与学习计划

建议使用一个可选的托管模型接口；供应商、模型 ID、价格和可用性待验证，当前未选定、未调用。只提供合成画像、已选职业、技能缺口、已核验资源、SDG 映射和来源片段，不允许自由补充事实。大模型不能创造职业、技能、课程或统计；输出中的职业、技能、课程和引用 ID 必须属于输入白名单；校验失败则使用模板。

学习步骤先按技能缺口和人工核验的先修关系排序，再结合每周时间计算安排。模型只辅助解释、拆解已有步骤和调整措辞；不能发明课程、统计或未提供的资格要求。展示所用模型、输入证据与运行版本，时间估算标记依据。

## 数据层与缓存

建议保存：职业/技能目录与映射、趋势原始快照和衍生信号、课程目录、SDG 定义与映射、合成画像版本、情景/规则版本、匹配运行及引用关系。仅使用 CSV/JSON 文件，不使用 SQLite；不保存账户或长期用户数据。

GitHub 快照保存查询词、查询时间（UTC）、两个相邻且不重叠的完整 90 天时间窗、各窗口返回计数、完整来源 URL、缓存时间及返回完整性状态。主题说明和过滤条件固定，窗口边界明确记录。匿名搜索按每分钟最多 10 次设计，两窗口查询共享预算；使用缓存避免频繁刷新，并遵守实际服务端限流响应。每个缓存结果显示原始来源、查询日期和窗口、缓存时间及 `cached` 标识；缓存有效期待验证。历史回放与合成测试输入分别标记。固定列表只能作为目录，不能冒充可更新趋势；模拟刷新不能冒充实时数据。

## 故障与降级

| 故障 | 计划降级 | 用户可见信息 |
| --- | --- | --- |
| 来源不可用或请求失败 | 使用最近有效且许可允许保存的快照；无缓存则停止趋势推荐 | 失败原因、`cached`、原始查询时间与缓存时间、来源及过期状态；失败不更新成功快照时间 |
| 来源结构变化或技能映射不足 | 保留旧有效版本，不把无效数据写入评分 | 覆盖不足、待验证映射及未更新状态 |
| 模型失败、超时或引用校验失败 | 使用规则生成的解释和已核验资源计划 | 模板模式；分数与引用仍可检查 |
| 没有可信课程或职业 | 标记缺项，展示有限结果 | 不足数量与待补充项，不生成替代事实 |

## 评分验收标准（计划中，待执行）

1. 同一输入、数据快照、映射和评分版本得到完全相同的全部中间值、总分及排序；超要求覆盖不超过 1，零要求项不参与对应技能或知识覆盖分。
2. 使用会产生不同非饱和 T 的趋势快照验证公式传递：T 的变化必须影响情景总分，排名可以变化但不强制变化；计数改变但因限幅得到相同 T 时须如实解释。
3. 情景对比仅改变 lambda；校验画像、O*NET 数据、原始趋势及其他规则完全一致。
4. 界面能解释并追溯所有中间分数、缺失原因、缓存和过期状态；零向量和缺失数据按文档降级，不伪造完整结果。
5. 大模型不参与分数计算，不可覆盖或优化分数；即使模型失败，规则结果保持一致。

## 学生路径证据重评实现（2026-10-22）

`src/evidence_reassessment.py` 负责显式刷新协调、前次成功证据保留、主题原始计数对比及独立情景实验；底层仍调用 `GitHubTrends.refresh()`，查询、缓存、限流和评分公式不变。无点击不获取证据；每次只处理一个已批准职业。失败或缓存命中不生成假的成功时间。

`pathway_evidence` 会话状态与原始 synthetic 画像评估快照分开。真实证据仅按职业自身映射传入 `rank_roles` 的副本，缺少证据不填入 demo 数值。只有完整三职业候选集合均可计算时展示该实验的排名；否则仅显示有效分项。官方数据继续执行缺失与质量阻断，不把合成要求替换成官方要求后假装完整真实排名。完整证据对比保留同一已确认画像；原合成排名用作明确标注的独立基准。

职业切换建议按用户选定的 Moderate/Fast 情景首位产生。用户确认前保持所选职业与计划不变；确认后由现有学习计划模块按新职业的合成缺口生成四周练习。切换与证据变化均不写回职业数据、趋势 fixtures 或评分规则。


## PDF CV 辅助录入实现（2026-10-22）

- `src/cv_pdf.py`：`pypdf==6.21.1`（[官方发行页](https://pypi.org/project/pypdf/6.21.1/)）是唯一新增直接依赖，无 OCR/加密额外依赖；通过 BytesIO 和严格解析读取，校验 .pdf、`%PDF-`、3 MB、1–5 页，提取可选择文字，最多在本地累积 50,000 字符。错误消息不包含文件内容或文件名；解析诊断不写出 CV 片段。不存在可提取文字则降级至问卷，不造空画像。
- `src/cv_client.py`：标准库 urllib 的 OpenAI-compatible **Chat Completions** 客户端。必须显式配置 `AI_BASE_URL`（例如供应商的 `/v1` 基址，也接受完整 `/chat/completions` URL）、`AI_MODEL`、`AI_API_KEY`，不选默认供应商、不读取或自动加载 .env 文件。环境须由启动进程注入；.env 已被 Git 忽略，.env.example 只有配置键。外部端点要求 HTTPS；本机服务可用 HTTP。禁止跟随重定向，避免向新端点转发文字和认证头。
- 客户端入口先检查 consent=True，再读取配置；本地去除常见邮箱、电话、URL、地址及带标签姓名，截断为 8,000 字符。脱敏是启发式，不能保证匿名化；界面提供待发送文字预览与供应商保留政策提醒。请求只有 system 抽取规则、字段白名单、处理后文本和模型参数；不发送 PDF、原始文件名、计分引擎、职业目录、GitHub 缓存或 API 密钥到提示词。认证密钥仅用于 Authorization 请求头，不展示或记录。
- 响应使用 JSON object 格式，客户端再验证固定字段、类型、数组长度、枚举、原文子串证据和简短经历摘录。禁止任意额外字段和模型赋分；技能/知识须在证据中出现其正式问卷名称，教育采用显式术语白名单（如 computer science→Computing、Bachelor/BSc→Bachelor's），不能从工作经历推断学历。无法验证的回复整体拒绝。30 秒超时、64 KB 响应上限，无自动重试；服务错误消息只给通用提示，不显示远端响应、请求内容或认证信息。
- `src/cv_intake.py`：两个录入入口、逐文件显式同意、人工编辑及第二次确认。原 PDF 只在 Streamlit 临时上传缓冲区与本次函数栈存在，不存自定义 session、磁盘、日志或 cache_data。模型处理成功/失败、解析失败、取消、离开录入步骤或切换模式时，移除上传管理器中的文件并轮换控件。会话只暂存受限模型字段和短证据供审核；确认后只写回原问卷字段与 `pathway_cv_context` 非计分短备注，不保存完整文本或原始模型响应。未确认的 review 可取消清除。
- 技能/知识的出现只是待自评提示，用户独立选择 0–4，不从文字猜测能力分。RIASEC 不从 CV 推断；所有缺失规则、最终画像确认、确定性评分与质量阻断保持原样。手填工作区和示例工作区继续分开，CV 采用结果写入手填工作区。计划导出白名单不包含 `pathway_cv_context`，恢复流程仍不读取 CV。

部署限制：当前同步 PDF 解析和模型请求适合小文件短流程，无后台持久任务。复杂排版、图片/扫描件和术语覆盖有限，尚未验证真实模型连通性及抽取质量。界面仍以英文显示，未实现 OCR、DOCX、多语言翻译、自动能力评级、模型匹配或长期 CV 存储。模型不可用时完整问卷、合成示例及计划恢复均可继续。
