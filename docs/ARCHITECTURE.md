# FutureShift AI — 建议架构

## 状态与最简方案

当前仅有文档，无应用功能。以下技术栈均为建议，尚未最终确定，也未安装或部署：单个 Python Streamlit 应用负责问卷、结果和对比界面；同进程 Python 模块负责数据获取、规则评分和可选模型调用；SQLite 保存版本及运行记录，JSON/CSV 保存小型目录与原始快照。适合单人短期构建可演示的计算链，避免独立前后端、向量库、任务队列与微服务。具体运行环境兼容性待验证。

## 前端

建议 Streamlit 页面按问卷 → 画像确认 → 雷达与情景 → 前五职业及缺口 → 学习计划组织。展示合成数据标识、来源与日期、情景假设、运行版本、更新前后对比及缓存状态。先满足预赛最关键演示；移动端体验待验证。

## 后端与数据获取

建议与前端同进程，职责分开：

1. 数据获取：读取经许可验证的公开来源，保留原始快照、原始 URL/记录标识、发布日期、获取日期、许可、地域、内容哈希及获取状态。手动触发真实获取即可，暂不建定时服务。
2. 趋势信号计算：清洗、去重、职业技能映射，按明确窗口和基线计算 AI 任务变化信号及劳动力市场信号；分别保留覆盖率、缺失情况、计算版本和证据。具体指标须经过数据验证后确定。
3. 情景参数：moderate / fast AI disruption 使用有依据的不同任务变化系数，保存假设、范围、版本及依据；不伪装为预测概率。
4. 可解释匹配：仅从已验证目录选职业，以固定公式生成分项与排序。
5. AI 解释与学习计划：读取锁定的计算结果和证据，生成表述；资源选择与先修顺序先由规则约束。

链路：来源快照 → 信号版本 → 情景参数 + 已确认画像 + 职业目录 → 规则评分 → 受约束解释与计划 → 结果及审计记录。先保留可复算记录，再生成文字。

## 匹配引擎

建议初版公式（设计提案，权重与尺度待验证）：`score = 100 × (0.50 × S + 0.20 × I + 0.30 × T)`，各分项归一化到 0–1。

- S：职业要求技能的加权满足程度，自评水平与要求水平使用相同刻度，超出要求的部分封顶；缺口按技能逐项输出。
- I：问卷兴趣与职业标签的规则重合度。
- T：分别计算有来源的市场信号 M 与 AI 任务信号 A，再按情景系数组合并限幅。例如 `T = clamp(0.5 + 0.5 × (M + c × A) / (1 + c), 0, 1)`，M、A 在 -1–1 范围，c 为版本化情景参数。A 的方向必须依据任务映射，不能简单认为 AI 进步利好或利空全部职业。

这是待检验的启发式适配分，不是就业概率。数据不足时不默认为零，也不静默重新分配权重；应标记证据不足并阻止把该结果作为完整趋势推荐。相同分数按稳定职业 ID 排序。精确归一化、技能权重和 c 值是编码前决策。

大模型无权生成、修改分数或名次。评分结果包含分项、权重、信号贡献、缺口、输入版本与引用，供解释层只读使用。数据更新演示需固定其他版本，以隔离真实信号变化的影响。

## AI 组件与学习计划

建议使用一个可选的托管模型接口；供应商、模型 ID、价格和可用性待验证，当前未选定、未调用。只提供合成画像、已选职业、技能缺口、已核验资源、SDG 映射和来源片段，不允许自由补充事实。输出中职业、课程和引用 ID 必须属于输入白名单；校验失败则使用模板。

学习步骤先按技能缺口和人工核验的先修关系排序，再结合每周时间计算安排。模型只辅助解释、拆解已有步骤和调整措辞；不能发明课程、统计或未提供的资格要求。展示所用模型、输入证据与运行版本，时间估算标记依据。

## 数据层与缓存

建议保存：职业/技能目录与映射、趋势原始快照和衍生信号、课程目录、SDG 定义与映射、合成画像版本、情景/规则版本、匹配运行及引用关系。小规模可用 SQLite 加本地文件，不先引入专门搜索或向量服务。

每个缓存结果显示原始来源及日期、获取日期、缓存标识与适用窗口；过期阈值按来源确定，尚待验证。历史回放与合成测试输入分别标记。固定列表只能作为目录，不能冒充可更新趋势；模拟刷新不能冒充实时数据。

## 故障与降级

| 故障 | 计划降级 | 用户可见信息 |
| --- | --- | --- |
| 来源不可用或请求失败 | 使用最近有效且许可允许保存的快照；无缓存则停止趋势推荐 | 失败原因、原始来源与日期、缓存获取日期、非实时及过期状态 |
| 来源结构变化或技能映射不足 | 保留旧有效版本，不把无效数据写入评分 | 覆盖不足、待验证映射及未更新状态 |
| 模型失败、超时或引用校验失败 | 使用规则生成的解释和已核验资源计划 | 模板模式；分数与引用仍可检查 |
| 没有可信课程或职业 | 标记缺项，展示有限结果 | 不足数量与待补充项，不生成替代事实 |

## 部署

先本地验证完整数据链，再选择单个应用运行环境。Replit：待恢复兑换后配置，尚未配置部署。RunPod：已有额度但尚未启动资源；当前方案不依赖 GPU，本轮不启动任何资源。SQLite 与文件存储的持久化能力需在部署选型后验证；密钥通过环境变量配置，不写入仓库。是否采用托管模型需先确认预算与使用方式。

## 隐私

演示仅使用合成画像，禁止真实 CV 和真实个人资料。问卷不收集姓名、联系方式等身份字段；日志只保留合成画像标识与必要计算记录。公开数据仍需核验许可与保存条件。后续真实用户或 CV 功能须重新设计授权、保留期限及删除机制。职业建议始终由用户判断，不用于自动招聘决定。
